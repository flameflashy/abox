# MCP: Elicitation та Sampling

## Вступ

Model Context Protocol (MCP) — це підхід для інтеграції AI-моделей з інфраструктурою, сервісами та користувачами через стандартизовані сервери.

У цьому документі розглядаються два ключові механізми:
- Elicitation
- Sampling

---

## MCP Elicitation

### Що це таке

Elicitation — це механізм, за допомогою якого MCP сервер запитує у користувача додаткову інформацію або підтвердження перед виконанням дії.

Тобто сервер не виконує дію одразу, а:
1. Аналізує, що даних недостатньо або потрібне підтвердження
2. Формує запит до користувача
3. Отримує відповідь
4. Продовжує виконання

---

### Як це працює

Типовий flow:

1. Користувач викликає дію (наприклад, deploy)
2. MCP server визначає, що не вистачає параметрів
3. Сервер викликає elicitation
4. Користувач вводить дані (наприклад, environment)
5. Сервер виконує дію

---

### Технічні кейси

- Запит namespace перед виконанням kubectl команд
- Підтвердження перед scale до 0 або delete ресурсу
- Запит параметрів для запуску CI/CD pipeline
- Уточнення конфігурації перед деплоєм (env, version, region)
- Запит credentials або token (через безпечний flow)

---

### Бізнесові кейси

- Підтвердження витрат (approve / reject)
- Узгодження заявок або задач
- Заповнення форми перед запуском процесу
- Уточнення даних клієнта перед обробкою запиту
- Approval workflow для production deployment

---

### Переваги

- Зменшує кількість помилок
- Дає контроль над критичними діями
- Робить AI більш "керованим"
- Покращує UX через інтерактивність

---

## MCP Sampling

### Що це таке

Sampling — це механізм, при якому MCP сервер запитує AI-модель (через клієнта) згенерувати або проаналізувати дані.

Важливо:
сервер сам не інтегрується напряму з моделлю, а використовує клієнта як посередника.

---

### Як це працює

Типовий flow:

1. MCP server отримує запит
2. Сервер формує prompt
3. Через sampling звертається до AI-моделі
4. Отримує результат (completion)
5. Використовує результат у відповіді або логіці

---

### Технічні кейси

- Аналіз логів та помилок
- Генерація summary для інцидентів
- Автоматичне пояснення помилок CI/CD
- Генерація конфігів або YAML
- Code review або linting через AI

---

### Бізнесові кейси

- Генерація звітів
- Підготовка відповідей клієнтам
- Автоматичне створення документації
- Аналіз звернень у support
- Генерація рекомендацій або інсайтів

---

### Переваги

- Додає "інтелект" до системи
- Зменшує ручну роботу
- Прискорює аналіз і прийняття рішень
- Дає можливість працювати з неструктурованими даними

---

## Порівняння Elicitation vs Sampling

| Характеристика | Elicitation | Sampling |
|----------------|------------|----------|
| Джерело даних | Користувач | AI модель |
| Основна ціль | Отримати дані/підтвердження | Згенерувати або проаналізувати |
| Тип взаємодії | Інтерактивний input | AI completion |
| Контроль | Високий (людина) | Частково автоматичний |

---

## Висновок

Elicitation та Sampling — це два ключові механізми MCP:

- Elicitation відповідає за контроль і взаємодію з користувачем
- Sampling додає інтелект і автоматизацію

Разом вони дозволяють будувати складні AI-driven системи, які:
- взаємодіють з користувачем
- приймають рішення
- автоматизують процеси
